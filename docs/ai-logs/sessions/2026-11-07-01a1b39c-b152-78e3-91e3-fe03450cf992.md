yes, our current lending code has a 24-hour cooldown between automatic moves of funds from one lending pool to another.

it’s a rule we configured in our app. CRE itself doesn’t require a 24-hour wait. Chainlink currently allows scheduled CRE runs as often as every 30 seconds. [official quotas](https://docs.chain.link/cre/service-quotas#cron-trigger)

here’s what our cooldown means:

- after a move finishes and the destination deposit is verified, the timer starts.
- for the next 24 hours, the decision logic returns `HOLD / COOLDOWN` instead of approving another move.
- monitoring can continue during that time. our default checking interval is one hour.
- withdrawal requests don’t use this cooldown, though an unfinished transfer can delay withdrawal.

for example, if a move finishes at 3 pm today, another automatic move becomes eligible at 3 pm tomorrow. it still needs to pass the profitability and fee checks.

the purpose is to prevent frequent back-and-forth moves that spend fees chasing changing rates. the duration is configurable: `cooldownSeconds` defaults to `86400` in [the plan settings](<project>/agent/lending.py:43), and [the decision logic](<project>/lending/decision.ts:208) enforces it.
